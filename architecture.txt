DATA DICTIONARY FIRST — V0.2
============================

Purpose
-------

A governed dictionary is both human-readable semantics and an executable
contract. V0.2 adds the adoption boundary: a formal external schema, stable
CLI behaviour, cross-domain examples and automated acceptance tests.

CLI / execution failures
------------------------

invalid CLI usage -------------------------------> exit 2
file I/O / malformed JSON / runtime input ------> exit 3

This distinction means pipelines can separate invalid governed data from data
that could not be evaluated.

Engineering boundary
--------------------

The dictionary is not documentation beside the system.

If a semantic rule matters operationally and can be expressed
deterministically, make it executable.

V0.2 adds a second rule:

If an engineering artefact is meant to be adopted, installation, contract
shape and failure behaviour must be recoverable without its author present.
